# T-MAC CPU Comparison

## Environment

- Original CPU: `Intel Core Ultra 7 258V`
- Lab CPU: `AMD Ryzen 5 8500G`
- Shape notation: `M×N×K`
- T-MAC modes: `W2A16`, `W3A16`, `W4A16`
- Final latency: median of five independent run-level medians.
- `Lab Speedup = Original CPU median latency / Lab CPU median latency`.
- `Lab Speedup > 1.0×` means the lab Ryzen CPU is faster.
- Original machine exposes 8 hardware threads; lab machine exposes 12 logical CPUs.
- 16T is retained for HackMD parity, but is oversubscribed on both machines.

### T-MAC W2A16 summary

- Best lab speedup: `2.120×` at `256x256x256`, `4T`.
- Lowest lab speedup: `0.888×` at `4096x4096x4096`, `8T`.

### T-MAC W3A16 summary

- Best lab speedup: `2.168×` at `256x256x256`, `4T`.
- Lowest lab speedup: `0.919×` at `4096x1024x2048`, `2T`.

### T-MAC W4A16 summary

- Best lab speedup: `1.553×` at `1024x1024x1024`, `1T`.
- Lowest lab speedup: `0.868×` at `1024x1024x1024`, `2T`.

## Interpretation Notes

- This comparison evaluates the same standalone AVX2/F16C/OpenMP T-MAC implementation on two different x86 CPUs.
- It is a cross-CPU performance comparison, not a microarchitecture-controlled experiment.
- W2/W3/W4 use different low-bit weight precisions, so comparisons between bit widths should not be interpreted as equal-precision arithmetic.
- The main latency value is `total_ms`; autotuning time is not included in the reported benchmark latency.
- 16T results are kept for compatibility with the HackMD thread sweep but should be interpreted separately because both machines are oversubscribed at 16 requested threads.
